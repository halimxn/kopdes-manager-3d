# Sumber SQL dan instalasi bersih

`supabase/migrations/` berisi sepuluh migrasi berurutan (1–10). Semuanya masih digunakan oleh tes database lokal dan generator reset; **tidak ada berkas migrasi yang terbukti tidak digunakan**, sehingga tidak ada yang aman dihapus sekarang. Menghapus migrasi historis yang pernah dijalankan membuat keadaan cloud sulit diaudit. Berkas reset adalah operasi destruktif tersendiri, bukan migrasi normal.

Untuk proyek yang benar-benar **belum memiliki skema aplikasi**, `supabase/install/INSTALL_SCHEMA_KOSONG.sql` adalah SQL tunggal yang menggabungkan seluruh migrasi dalam satu transaksi. Dibuat ulang dengan `node scripts/build-install.mjs`. Berkas ini menolak berjalan bila tabel aplikasi sudah ada; jangan jalankan pada proyek Kopdes yang sekarang berisi data atau sudah terpasang. Uji lokal di `tests/database/install-schema.test.ts` memeriksa pemasangan dan penolakan instalasi ulang.

Untuk proyek Supabase saat ini `<project-ref>`, pakai hanya migrasi tambahan yang belum terpasang setelah **memeriksa keadaan cloud**. Status penerapan migrasi 6 dan beberapa migrasi sebelumnya belum sepenuhnya terverifikasi di `STATUS.md`/`CHECKLIST.md`; jangan menebak atau mengulang reset. Sebelum SQL cloud apa pun: sebutkan berkas, dampak, proyek tujuan, dan minta persetujuan pemilik sesuai `AGENTS.md`. Jangan jalankan SQL dari panduan ini secara otomatis.

**Migrasi 8 — `20261006000008_world_logistics.sql` (6 Oktober 2026; menurut pemilik berhasil dijalankan di cloud pada hari yang sama).** Menambah jenis catatan `deliveries` (Pengiriman) dan `stock-movements` (Mutasi stok), relasi `delivery_id`/`stock_count_id`, validasi arah/status pengiriman dan jenis/jumlah mutasi, larangan mengubah mutasi, fungsi atomik `hub_post_stock_movement` (mengunci barang, menolak stok negatif, mencatat stok sebelum/sesudah) serta `hub_logistics_ready`. Fungsi hanya untuk `service_role`. Tidak menghapus tabel, data, atau RLS. Prasyarat: migrasi 2–7 terpasang. Sebelum migrasi 8 terpasang, halaman Pengiriman menampilkan "belum aktif" dan dunia tidak memuat data logistik. Diuji di PGlite (5 tes).

**Migrasi 9 — `20261013000009_report_backup.sql` (13 Oktober 2026; belum dijalankan di cloud).** Menyelaraskan kolom status laporan lama dengan status snapshot yang dipakai UI dan memperbarui `restore_manager_data` agar status draf/final dipertahankan saat pemulihan. Tidak menghapus data saat migrasi; pemulihan yang dipanggil pengguna tetap mengganti catatan/laporan secara atomik. Hak fungsi tetap hanya `service_role`; RLS tidak berubah. Prasyarat: migrasi 1–8. Target: proyek Supabase baru milik pemilik, project ref harus dikonfirmasi sebelum pemilik menjalankannya. Jangan memakai reset/install untuk memperbarui proyek yang sudah berisi data.

**Migrasi 10 — `20261015000010_administrasi_usaha.sql` (15 Oktober 2026; belum dijalankan di cloud).** Menambah lima jenis catatan: `assets` (Inventaris aset), `attendance` (Jadwal & absensi), `purchase-orders` (Pembelian), `sales` (Penjualan harian), `savings` (Simpanan anggota); relasi `purchase_id` dari pengiriman ke pembelian; validasi status/kondisi/jenis dan angka bulat; indeks unik satu absensi per petugas per hari dan satu penjualan per gerai per hari; penolakan penarikan simpanan yang melebihi setoran per anggota dan jenis (baris anggota dikunci); fungsi `hub_administration_ready` hanya untuk `service_role`. Tidak menghapus tabel, data, atau RLS; mengganti isi `hub_check_relations` dengan daftar relasi yang sama ditambah `purchase_id`. Prasyarat: migrasi 1–9. Sebelum terpasang, kelima halaman menampilkan "belum aktif". Pemulihan cadangan menyisipkan catatan sesuai urutan cadangan; penarikan simpanan yang tercatat sebelum setorannya akan ditolak. Diuji di PGlite (4 tes). Target: proyek Supabase milik pemilik; project ref dikonfirmasi pemilik sebelum dijalankan.

Setelah perubahan skema berikutnya, tambah migrasi bernomor baru, jalankan tes database lokal, lalu bangun ulang SQL instalasi bersih dan reset dengan generatornya. Bila ada file yang diduga tak dipakai, buktikan bahwa tidak dirujuk kode, tes, generator, docs, serta belum menjadi bagian riwayat cloud sebelum menghapusnya.
